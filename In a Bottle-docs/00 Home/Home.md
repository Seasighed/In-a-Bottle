## Documentation Rules

- Search for an existing note before starting a new one.
- Keep feature notes focused on behavior, surfaces, and dependencies.
- Keep system notes focused on architecture, services, and integrations.
- Keep logic notes focused on rules, state transitions, and constraints.
- Update user notes whenever a behavior change affects how someone uses the project.
- End every changed note with a concise `## Change Log` entry.
